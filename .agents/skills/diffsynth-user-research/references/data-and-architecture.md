# 数据、表示与架构实验

适用于数据分布/监督研究、从零训练、表示与结构修改、泛化和遗忘。源码入口：`diffsynth/core/data/{unified_dataset,operators}.py`、目标训练Dataset/输入映射、`diffsynth/models/`、`docs/zh/Research_Tutorial/train_from_scratch.{md,py}`。常规数据准备可读取可用dataset专项，但实验设计仍由研究目标决定。

## 数据与监督研究

| 问题 | 可操作的研究因素 | 对照与验证 |
| --- | --- | --- |
| 数据规模与覆盖 | 子集大小、长尾重采样、领域/任务比例、课程 | 区分独立样本量、总曝光数、有效更新数，报告各预算 |
| Caption与条件 | 清洗/改写、文本长度/语言、结构化标注、条件dropout | 保留原始版本，检查真实编码与截断；生成标注注明来源 |
| 预处理与增强 | 分辨率、长宽比、裁剪、颜色/空间增强、视频取帧、音频采样 | 对齐target和条件，分析增强是否改变监督语义 |
| 数据质量 | 去重、质量阈值、reward筛选、噪声标注 | 等量或等训练预算对照；筛选评分器与最终独立评价分开 |
| 合成数据与自训练 | 搜索/编辑生成、真实/合成混合、困难样本和偏好对 | 保存生成模型、条件、seed、选择规则，防止自评闭环与来源泄漏 |
| 泛化与保持 | 少样本、跨主体/风格/领域、组合泛化、重放与持续学习 | 按主体/来源分组留出；旧任务/新任务分别评价，检查记忆和遗忘 |

`dataset_repeat`增加曝光，不增加独立样本；`max_data_items`直接控制Dataset长度，并用取模访问记录，也不是自动采样出这么多不同数据。比较数据规模时实际构建明确子集，保存来源ID及划分，不把重复遍历称为扩充数据。

字段链路必须核对 `metadata → data_file_keys/operator → get_pipeline_inputs/extra_inputs → 消费者`。special_operator_map只处理进入加载键的字段，extra_inputs本身不打开文件；有些条件从目标媒体派生，例如首帧，不应一律要求独立列。编辑区分source与target，多参考保留列表顺序。结构化prompt/嵌套媒体按目标processor验收，不能统一转字符串。

JSON/JSONL保留列表和对象类型，CSV字符串列表不等于真实list。当前JSONL空行会解析失败；metadata_path=None走 `.pth` 缓存搜索，不是扫描原始媒体。路径根、裁剪/缩放、帧数/fps、音频采样率按实际operator检查，再抽样查看返回值与输入映射。只解释格式不转换数据；用户要求准备时才生成新metadata/必要媒体，原数据保留。

当前 `LoadTorchPickle` 用 `torch.load(..., weights_only=False)` 读取缓存，可能执行pickle反序列化代码；`.pth`后缀或来自数据目录不表示可信。只加载已核对来源的缓存，未知来源先静态调查；需要重建时用可信原始数据和代码生成，并保留新旧缓存的配置与来源映射。

视频片段、同源合成图、多版本caption、相同主体参考和近重复不能随机散落训练/测试而声称独立。数据规模变化时明确固定更新数、固定总曝光还是固定epoch；这些回答不同问题，可分别形成预算曲线。记录每组有效数据量、失败/排除和选择成本。

## 表示与模型结构研究

| 改动层 | 可以研究什么 | 必须核对的契约 |
| --- | --- | --- |
| 文本/条件编码 | hidden layer选择、token长度、投影、冻结/联合训练、多模态条件融合 | tokenizer/chat模板、mask、embedding维度及正负条件语义 |
| VAE/数据表示 | 压缩率、latent归一化/尺度、编码噪声、重建瓶颈、空间与时间压缩 | encode/decode匹配、latent分布、分辨率整除及媒体边界 |
| 去噪主干 | 深度/宽度/head、patch、位置编码、归一化、FFN、条件融合、稀疏/MoE | head_dim、token/位置布局、输入输出通道、初始化及预训练键兼容 |
| 目标与噪声定义 | 参数化、噪声插值、训练采样和预测转换 | noising、target、weight与采样step成套一致 |
| 系统组合 | 模块共享、双塔/多分支、逐阶段、动态计算 | 新参数是否被优化、各分支实际执行、保存与调度关系 |

这些是项目层可实现的研究方向，不是现成一键训练功能。普通SFTloss未必支持VAE重建训练或新的表示目标；需设计真实loss和可微路径。像素空间模型、统一理解/生成模型、音视频双流也不能套独立TextEncoder—DiT—VAE的固定假设。

架构对照同时记录参数量、实际token、训练更新、计算与数据，不能只固定epoch就把效果归因于结构。修改patch/压缩率会改变token数量与动态schedule，必要时单列控制。改变组件后重建对应特征缓存，核查LoRA目标层及量化/VRAM映射，不继续使用过期注册信息。

## 从零训练的最小闭环

以教程 `docs/zh/Research_Tutorial/train_from_scratch.py` 为起点，复制到用户项目。当前AAADiT随机初始化denoiser，但Qwen3-0.6B文本编码器和Flux2 VAE是预训练的；报告确切“从零”范围、冻结组件及其权重成本，不称整个系统从零。

原例 `max_data_items=10000000`、`num_epochs=999999`依赖人工停止。先改有限真实子集、epoch或项目实现的有效update上限与保存间隔；`--max_train_steps`不是通用CLI现成参数。检查 `data/images`、`data/metadata_merged.csv` 等真实路径，不自动下载教程大数据代替用户输入。

可以按资源调整denoiser深度/宽度等，但先推导head整除、输入latent与文本维度；保留预训练组件接口，避免尺寸表面能跑但语义错位。先完成真实batch → forward/shape → 一次有效backward/update → 保存 → 新进程推理，再扩大规模。训练分辨率、归一化、target和推理调度一致；CFG实验还需检查训练是否提供相应无条件学习，不能仅因为推理能设CFG就认定已学会。

架构和初始化配置与checkpoint共同保存，明确哪些冻结状态可从固定预训练来源重建，哪些buffer/状态必须额外保存。预训练权重局部迁移要列出加载/随机初始化的参数范围；结构键匹配不证明语义兼容。正式注册/converter/module map是后续框架接入工作，项目Pipeline可直接挂载自定义模块。

## 解释训练结果

loss下降只证明优化当前目标，不能代替生成质量/泛化。小数据模型可能记忆训练集；同时查看训练样本重建、留出主体/组合/条件、无关输入和多seed。预先区分smoke、探索pilot和支持正式结论的规模。训练中断交付已完成更新、实际checkpoint、未恢复状态与继续条件，不把后台存活或文件已生成当作训练完成。
